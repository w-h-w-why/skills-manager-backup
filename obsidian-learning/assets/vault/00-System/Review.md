# 间隔复习

使用学习者时区的当地日期比较到期日。间隔复习借鉴遗忘与提取练习思路；默认 `[1, 3, 7, 14, 30]` 天只是产品初始参数，不宣称是艾宾浩斯曲线推导出的个人精确规律。

## 安排算法

每个能力保存 `review_stage`（0 起）、`last_review_at`、`next_review_on` 和最近证据。首次有学习依据时阶段为 0，下次为当天加第 0 个间隔；尚未验证掌握的条目注明是巩固/诊断，不授予掌握状态。纯跳过且没有学习依据的条目留在缺口列表。

每次实际复习依据新表现更新：

- **独立成功**：不依赖提示的回忆与应用成功；阶段加 1，封顶为最后阶段，下次从实际完成日加该阶段间隔。达到完整掌握标准时才标为 verified。
- **提示后成功或不稳定**：阶段不变，下一次采用该阶段间隔的一半，向上取整且至少 1 天；保留以前的掌握证据，当前状态标为 needs-review。
- **无法回忆或明显误用**：阶段回到 0，下次为实际完成日加首个间隔，当前状态标为 needs-review；补足关键缺口后再验证。
- **跳过/未作答**：不增加阶段、不更新 last_review_at，不计为失败。原到期日保留，若用户明确推迟，另记 `deferred_until` 和原因，便于再次安排。

每个基础或应用场景能力分别计算；从事件恢复时，同一事件 ID 的更新只应用一次。计算跨月日期时用日期库或可靠工具，不能直接给日字段加数字。用户可调整间隔，记录采用的参数与理由。

## 每次会话的复习选择

默认占本次学习时间 20%–30%，优先顺序为：影响本次新课的前置能力、当前目标相关且薄弱的能力、其他到期能力。同等级再参考逾期时长。给出少量回忆题、变式或任务，而非直接展示原笔记让用户重读。

用户可选择专门复习或直接学新课。积压时保留剩余队列，避免一回来必须清完；逾期本身不会改变掌握状态。每次复习后按 Storage 协议更新证据、能力和队列。

没有后台调度时只在进入会话时检查。不得宣称已经设置提醒或将在某天主动出现。
