# 文件、证据与恢复协议

## 目录与权威记录

| 路径 | 用途 |
|---|---|
| `00-System/` | 入口、偏好、状态、索引和操作协议 |
| `10-Courses/<course-id>/Course.md` | 目标、诊断摘要、路线、来源与完成标准 |
| `10-Courses/<course-id>/Progress.md` | 当前单元、未完成题目与作答、缺口、下一步 |
| `10-Courses/<course-id>/Units/` | 单元讲解、练习与独立答案 |
| `20-Knowledge/` | 共享知识点及关联 |
| `30-Learning/Abilities/` | 每个基础/场景能力的状态、证据引用和复习安排 |
| `30-Learning/Events/` | 每次实质变化的证据与提交记录 |
| `40-Sources/` | 链接阅读记录、知识提取、来源冲突与纳入结果 |
| `50-Ideas/` | 原始想法、整理、agent 延伸及发展记录 |
| `90-Templates/` | 新笔记模板；不算课程或学习证据 |

文件夹相对仓库根目录。文件名在 Windows 上合法，使用稳定 ID 加简短标题；重名时加后缀，不覆盖。新建前搜索已有 ID、名称、别名与内容。链接使用 `[[目录/文件名|显示名]]`，不带 `.md`；重命名需同步入链。优先链接已有完整笔记，待展开知识点可建明确标记 `stub` 的简短笔记。

时间戳用带偏移的 ISO 8601；到期日用学习者时区的 `YYYY-MM-DD`。未知字段用 `null` 或明确“待验证”，不推测补齐。frontmatter 中空值和状态必须合法，带特殊字符的字符串加引号。用户文本作为内容写入，不能拼接执行命令。

课程进度以 `Progress.md` 为准；能力掌握与复习日期以能力笔记为准；事件保留判断依据。State、Catalog 和 ReviewQueue 为指针/索引，不另造一套互相竞争的证据。

## 每次实质变化立即保存

触发：目标确定、诊断作答、练习提交、掌握判断、缺口发现、路线变化、想法记录，以及中断时已有的部分作答。普通对话无需逐条归档。

1. 读取将修改的文件，确认没有其他 agent 的未完成事件。创建唯一事件 ID（本地时间加随机后缀）；用 Event 模板写 `status: pending`、用户实际证据、判断理由、拟修改路径和恢复操作。
2. 将 `State.pending_event` 指向该事件。更新必要的能力、课程进度、知识或想法文件，再更新目录、复习索引和活动课程指针。尽量采用同目录临时文件替换单个文件；这种写法不等于跨文件事务。
3. 回读修改，检查证据引用可解析、下一步和未完成题目完整、复习队列与能力日期一致、答案暴露状态正确。事件标为 `committed`；最后更新 `last_event`，清空 `pending_event`。
4. 验证后简短告知保存结果；部分失败时保留 pending 事件和待办路径，明确哪些尚未同步。

## 中断与多个 agent

启动时除 State 指针外，还检查 Events 中的 pending 事件，处理“事件已写但指针尚未写”窗口。按该事件逐项比对实际文件与计划，只补缺失改动；以事件 ID 去重证据，不能重复增加复习阶段。已提交但 State 未更新时只修索引和指针。

第一版采用单写者协作：发现其他 agent 正在写入时不并发更改同一档案；若可确认旧会话已中断则执行恢复，否则说明冲突并暂缓写入。覆盖前再次检查文件是否变化；遇到变化重新读取并合并，保留用户编辑。

## 最小恢复信息

Progress 必须明确：当前单元与教学环节、未完成练习的题目/引用、用户部分答案、已给提示和是否展示答案、下一步动作。仅写“学到第二课”不足以恢复。

每次事件保留必要原文或忠实摘要，注明是哪一种。用户要求修改记录时追加更正依据并更新当前状态；要求不再记录想法时写入 Profile 偏好。删除要求按明确范围执行，同时修复相关链接和索引。
