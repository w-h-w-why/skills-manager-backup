## 文档维护

- 修改前读取本任务涉及的需求、业务与架构规则；开始任务更新当前任务入口。
- 每批代码、测试、配置或脚本修改完成后，主动核对当前实现和相关文档；纯格式/注释修改也检查，未改变事实可免写。验证带来新修改后复查，提交或交付前兜底。
- 按 [文档维护流程](docs/doc-maintenance.md) 的写入时机同步需求、接口、模型、环境、测试、决策与任务状态，无需用户提醒。
- 文档中的真实文件引用、索引和目录导航使用相对路径的 Markdown 链接；目录层级使用带链接的列表，尚未创建文件标注待创建，改名或移动后修复引用。
- 发现描述过期立即更新；发现代码违反明确约束或依据不明立即提出并给出原文、代码证据和影响，保留约束，只暂停依赖裁决的工作。
- 文档同步和必要验证完成后才能标记相关任务完成；相同事件更新已有条目。交付说明检查和修改了哪些文档、验证结果及未决事项。
