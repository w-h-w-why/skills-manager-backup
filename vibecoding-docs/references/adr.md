# ADR 写入规则

重要架构、技术选型、重要依赖或外部服务决策被确认时记录，普通实现细节不写 ADR。未确认方案可以保存为提议，不能标为已采纳。

创建前扫描实际 ADR 目录，取既有最大编号加一，四位零填充，不复用已有编号。并行任务由一个负责人分配；写前再次确认目标文件未存在。

使用 [ADR 模板](../assets/templates/adr.template.md)。记录日期、状态、背景、决策、替代方案与后果。区分已采纳和已实现，实施完成时收尾更新架构说明。

推翻旧决定时创建新 ADR 并链接旧编号。原 ADR 只更新状态、取代关系或修正明显笔误，保留原始理由，不能改写成当年选择了新方案。
