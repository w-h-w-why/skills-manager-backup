# 文档职责

示例文件名不等于强制布局。生成项目文档时将已存在文件名改成真实相对 Markdown 链接；不存在的推荐文件标待创建。

| 文件（示例） | 职责 | 更新 |
| --- | --- | --- |
| README | 定位、最短启动流程、目录与导航 | 当前事实原地改 |
| AGENTS | 项目特有约束、短收尾约定、Skill 入口 | 只在初始化或明确授权安装/改规则时改 |
| CONTEXT.md | 沿用现有领域上下文或会话入口职责 | 规则与事实原地改；总览链接详细主文档 |
| TODO/现有任务系统 | 当前任务、验收、下一步、待决 | 状态更新，不编造已完成 |
| CHANGELOG | 用户可见版本变化 | 历史保留，未发布去重 |
| .env.example | 变量、用途、假值、必填与加载说明 | 随配置变更，无真实秘密 |
| docs/README.md | 已存在主题文件索引和目录导航 | 链接随文件增删移动更新 |
| prd | 用户、目标、范围、非目标、验收 | 已确认需求原地改 |
| context/领域文档 | 业务规则、权限、状态语义 | 与已有 CONTEXT 同职责则合并或引用 |
| architecture | 当前模块边界、依赖与数据流 | 原地改，决策原因链接 ADR |
| data-model | 实体、关系、字段语义与约束 | 链接真实 schema，不复制整套机器定义 |
| api/现有契约 | 认证、错误、接口使用语义 | 与现有机器契约保持一致 |
| testing | 测试命令、策略与验收方式 | 区分实跑和未运行 |
| setup | 开发环境完整准备流程 | 与 README/变量模板同步 |
| glossary | 当前术语与命名 | 更新定义，标明废弃名称 |
| adr | 为什么选择某方案及取舍 | 见 [ADR 规则](adr.md) |
| notes/progress | 接续工作需要的成果、证据与下一步 | 同任务去重，不复制待办全表 |
| notes/known-issues | 现象、条件、影响、绕过、解决状态 | 更新原条目，保留历史 |
| deployment/security/operations | 实际运行、权限、安全、备份与故障规则 | 有实际需求才创建 |
| CONTRIBUTING | 人类协作、评审、提交约定 | 已授权规则原地改 |
| LICENSE | 权利人指定的授权条款 | 未指定则保持未指定 |

现状、规范和历史可以同文件共存，但必须明确：代码是当前实现证据，明确规范是约束；实现偏离约束不能通过静默改文档合理化。总览中同一信息只保留必要摘要和来源链接。

核对实现只读受影响范围；全面审计依用户范围展开。纯死链审计直接使用 [链接规范](links.md)。

有常用模板的主题见 [模板目录](../assets/templates/)；导航索引采用 [docs/README 模板](../assets/templates/docs-index.template.md)，新决策采用 [ADR 模板](../assets/templates/adr.template.md)。模板仅提供结构，实际路径由初始化适配。
