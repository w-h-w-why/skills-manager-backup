# 项目文档维护规则

本文件是开发过程中必须执行的文档维护流程。路径以当前项目为准，首次安装时将下面的默认路径映射到已有文档，并把主文档列中的已有文件替换为相对于本文件的 Markdown 链接；文件不存在时按“写入纪律”选择合并或新建。

## 执行时点

1. 开始任务前，读相关约束与文档，确认验收标准；已有 TODO 任务移到进行中。
2. 需求、业务规则或重要决策被确认时写入相应文档。正在讨论的方案保留待决状态，不能写成已采纳。
3. 每批有逻辑关联的代码、测试、配置或脚本修改完成后，立即执行开发巡检，处理相关文档，不等下一次会话或用户提醒。无需每次保存一个字符就重复巡检。
4. 验证后的修改、新发现或回退改变了事实时，再巡检受影响内容。没有新变化无需重复运行相同检查。
5. 准备提交、PR 或最终交付前兜底检查；先完成文档同步，再声明相关任务已完成。
6. 发现冲突时立即提出，不能等收尾才报告。

## 写入时机表

多种事件命中时合并处理。表中的“立即”指事件被确认、问题被发现或一批实现完成时，不是只在最终回复前处理。

| 事件 | 何时写入 | 主文档 | 写入内容与动作 |
| --- | --- | --- | --- |
| 初始化/接手项目，缺少必要上下文 | 执行建档或第一次需要该信息时 | README、AGENTS、相关 docs | 按事实补齐，安装维护入口；不建空文件 |
| 需求新增、删除、验收标准或非目标变化 | 用户确认后，依赖该需求的实现之前 | docs/prd.md | 原地更新目标、边界、状态与验收标准 |
| 业务规则、权限、状态流转或领域约束变化 | 获确认时；实现后核对 | docs/context.md | 更新当前规则与边界条件；相关模型也同步 |
| 新概念、术语含义或统一命名变化 | 首次成为项目约定时 | docs/glossary.md | 更新当前定义；废弃词指向新词，避免旧定义仍像有效规则 |
| 开始任务 | 开始实施前 | TODO.md 或现有任务入口 | 标进行中，保留可检验的验收条件 |
| 重要架构/依赖/外部服务决策 | 方案被接受时；实现后核对架构 | docs/adr/、docs/architecture.md | 新 ADR 记录原因与取舍；架构说明当前实施状态 |
| 模块职责、目录、数据流或依赖关系变化 | 本批实现完成后 | docs/architecture.md | 原地更新当前边界；重要取舍另记 ADR |
| 表、字段、约束、关系、持久化或状态机变化 | 本批实现完成后 | docs/data-model.md；必要时 context | 与当前 schema、迁移和代码对齐；说明兼容和迁移影响 |
| API、请求/响应、认证、错误、分页或事件协议变化 | 本批实现完成后 | docs/api.md 或现有 OpenAPI 等契约 | 更新对应契约及使用说明；接口源文件与说明不重复维护完整字段 |
| 环境变量新增、删除、默认值或读取方式变化 | 本批实现完成后 | .env.example、docs/setup.md | 更新键、用途、假值、必填性和加载方式；不复制真实秘密 |
| 安装、启动、构建、目录或开发工具变化 | 本批实现完成后 | README、docs/setup.md；需要时 AGENTS | 更新实际命令和步骤；各处保留的短命令同步 |
| 测试命令、策略、必要覆盖或 CI 检查变化 | 本批实现完成后 | docs/testing.md | 更新如何验证及检查范围；不虚报已通过 |
| Agent 规则或协作规范变化 | 已授权的约定改变时 | AGENTS.md 或 CONTRIBUTING.md | 原地更新，详细规则引用对应文档 |
| Bug 修复或用户可见行为变化 | 本批实现完成并核对后 | 相关行为文档、CHANGELOG.md 未发布区 | 记录可观察变化；未完成的尝试不写成成功修复 |
| 纯内部重构、格式/注释修改 | 本批修改完成后 | 检查相关架构/开发文档 | 没有改变文档事实时免写，不为凑记录添加 CHANGELOG |
| 发现既有代码和文档不一致 | 发现当时 | 受影响的主文档；必要时 known-issues | 按下方冲突分类处理，不把未查明来源的改动归功于本任务 |
| 踩坑、限制或临时绕过 | 确认存在时 | docs/notes/known-issues.md | 现象、条件、影响、证据、绕过及当前状态 |
| 完成任务 | 实现和必要验证满足验收标准后 | TODO.md；必要时 CHANGELOG | 标完成并带日期；验收未满足时保持未完成 |
| 阶段交接/会话结束 | 有实质成果或待接续事项时 | docs/notes/progress.md、TODO.md | 简短记录实际成果、验证、未完成项与下一步；复用任务条目 |
| 发布版本 | 版本与发布日期确认时 | CHANGELOG.md；需要时 deployment | 将未发布内容归入版本；不编造发布日期或部署成功 |
| 部署、权限、备份、告警或运行约束变化 | 本批已授权变更完成后 | docs/deployment.md、security.md、operations.md | 按需更新当前运行规则，不能为了验文档执行生产操作 |

## 开发巡检

### 1. 确定范围

读取当前变更集合和实际文件，区分原有用户改动、本次改动及并行 Agent 改动。代码含功能、测试、构建/运行配置、依赖声明、脚本和基础设施配置。格式、注释和文件重命名也纳入检查范围。

沿依赖查看接口、调用处、模型、运行命令和相关测试，而不是只看改过的行。根据写入表列出可能受影响的文档，逐一读取；文档不存在时仍检查是否需要承载该信息。

### 2. 比对当前状态

核对实现与文档的行为、签名、配置、路径、命令、模块关系及状态。测试是验证证据，不代替阅读当前实现；diff 是定位线索，不代替当前文件。每个相关文档得出：一致、描述过期、约束冲突、依据不足四种结论之一。

### 3. 分类处置

| 分类 | 判据 | 动作 |
| --- | --- | --- |
| 一致 | 当前实现与适用规则相符 | 不改文档；保留已检查结论 |
| 描述过期 | 文档是实现说明，本次已授权变化使其陈旧 | 立即原地更新说明、链接和相关记录 |
| 约束冲突 | 代码偏离明确需求、非目标、业务规则、依赖约束或禁止事项 | 立即向用户指出原文位置、代码证据和影响，说明改实现/正式改规则两条处理方向；保留现有约束 |
| 依据不足 | 意图不明、文档互相矛盾或实现尚未验证 | 立即提出具体待决点，记录证据，保持未确认状态 |

已有用户指令明确改变某个规则时，按授权更新规则并记录原因；先前授权不能从未回复或时间经过中推断。代码违反约束也不能通过静默修改文档变成合理行为。

发现冲突后立即给出具体说明；需要裁决时提出一个能解开冲突的问题。只暂停依赖该裁决的实现，继续无争议且已授权的工作。冲突未决时可以交付已完成部分，但相关任务保持待裁决状态。

### 4. 写入并检查

局部更新受影响文档，再核对当前实现，避免修订后仍留下旧例子、旧字段或失效导航。验证失败、回退实现时，同步恢复“现在是什么”的说明，保留尝试记录；不能留下成功完成的表述。

## 写入纪律

- 写前重新读取目标文档；使用小范围修改，保留用户已有内容与其他任务改动。
- 同一信息只有一个主文档。迁移重复内容时保留必要引用；环境变量和接口 schema 等机器文件是字段定义的来源，说明文档补充语义，不复制整套契约。
- 找不到目标文件时，先找同职责已有文件。信息短且有合适归属就合并；有独立价值和持续维护需求才新建。只添加真实已知内容，待确认点明确标注。
- 现状描述更新后删除被替代的旧描述；历史记录保留。已发布 CHANGELOG 保持历史，未发布区可整理去重；进展同一次任务更新已有条目。
- ADR 按实际目录扫描编号，最大四位编号加一；记录日期、状态、背景、决策、替代方案、后果。推翻旧决策建新 ADR 并引用旧编号；旧 ADR 只更新状态/取代指向，不重写原理由。
- known-issues 解决后更新原条目的状态、解决日期和证据，保留现象及处理历史。
- 同一事件重复巡检时更新已有条目，不反复追加 TODO、CHANGELOG 或 progress。验收失败后更新任务状态，不虚增“已完成”。
- 多 Agent 共用文档时指定一个维护负责人。子 Agent 报告触发事件和证据；由负责人分配 ADR 编号、更新任务与历史，写前再次读取共享文件。

## 链接与导航

- 引用实际存在的文档、源码、配置或目录时，使用 `[显示名称](相对路径)`，不要只留下不可跳转的文件名。路径以当前 Markdown 文件的位置为基准。
- README、文档索引和目录导航使用 Markdown 链接列表或链接表格。需要展示目录层级时使用带链接的缩进列表；可另附纯文本树，但纯文本树不能作为唯一导航。
- 维护触发表、相关文档区、ADR 的旧决策引用、known-issues 的实现证据等也使用真实链接；改名、移动或删除文件时同步修复相关引用。
- 尚未存在的推荐文件、示例路径和命令中的路径可以保留为普通文字或代码，标注“待创建”或“示例”；不能为了可点击而指向不存在的目标。
- 路径有空格时使用 Markdown 尖括号目标，或进行合适的 URL 编码。标题锚点只引用实际存在的标题；源码行定位只在项目使用的查看方式支持时添加，否则先保证文件链接可达。
- 下列是写法示例，不是项目实际导航；初始化时用已存在的文件替换示例目标：

```markdown
- [项目说明](../README.md)
- [需求文档](./prd.md)
- [业务上下文](../CONTEXT.md)
- [架构决策目录](./adr/)
  - [数据库决策](./adr/0001-database.md)
- [相关实现](../src/orders.ts)
```

## 验证与交付

先静态检查文件、链接、脚本定义、接口/schema、环境变量读取点与规则；再运行与变更相关且已授权的本地测试、类型检查、lint 或构建。复用有效的既有检查结果，没有新变化不重复运行。

验证文档不意味着执行部署、数据库迁移/重置、真实外部写入、生产操作或无限运行的服务。这些需要与任务匹配的授权和环境。命令仅检查定义但未实跑时，明确写“静态核对，未运行”；失败与未执行不能写成通过。错误证据摘录时去除密钥、token 和个人敏感信息。

开发任务包含代码修复时按原范围解决；纯文档任务发现代码问题时记录证据和待办，不扩大为代码改造。

交付前：相关文档已经逐一核对；触发事件都有处理结果；实际文件引用可点击且链接/路径存在；验收与运行结果真实；未决冲突已提出且任务状态正确。最终报告文档更新、验证证据和仍需裁决的事项。
