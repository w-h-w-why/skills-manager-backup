# 按事件写入细则

本文件按命中事件读取，不是每次编辑必读文件。默认写入时间是一次任务交付、提交或交接前；明确约束冲突和重要决策确认在发现时处理。主文档路径沿用项目现状。

| 事件 | 写入时间 | 内容 |
| --- | --- | --- |
| 需求、验收、非目标变更 | 收尾；后续实现依赖新规则时可先写 | 已确认目标与验收；待议方案保持待决 |
| 业务、权限、状态与术语变化 | 收尾 | 当前规则与边界；不以缺陷降低原规则 |
| 架构、重要依赖、外部服务决定 | 确认时记录理由，收尾核对实现 | 见 [ADR](adr.md)；区分采纳与实施 |
| 模块、数据、API 变化 | 收尾 | 当前边界、schema/接口及兼容影响；机器契约不复制完整字段 |
| 环境变量、运行、安装变化 | 收尾 | 键、假值、必填性、默认值和读取方式；README 与 setup 中保留的命令同步 |
| 测试策略、命令、CI 变化 | 收尾 | 真实定义、必要覆盖和验证结果 |
| 用户可见修复或功能 | 收尾 | 相关行为说明与 CHANGELOG 未发布区；内部格式调整不凑记录 |
| 完成、暂停、交接 | 收尾 | TODO 的真实状态；progress 仅记交接证据和下一步 |
| 已知限制或临时绕过 | 收尾 | 原问题更新现象、条件、影响、绕过与解决状态 |
| 文件新增、移动、删除 | 收尾 | 出链和入链，见 [链接规范](links.md) |
| 主题目录或索引结构变化 | 收尾；用户明确要求整理时执行迁移 | 按职责归档正文，更新根索引、主题索引和跨目录相对链接；一份事实只保留一个主文档 |
| 发布版本 | 版本与日期确认时 | 未发布归入真实版本，不编造日期和上线成功 |

## 差异处置

实现说明陈旧且本次变化已授权：更新当前事实。明确规则与实现冲突：即时报告原文、代码证据和影响，保留约束，只暂停依赖裁决的工作；已获授权的规则变更不重复确认。依据不足：标待确认。

更新前重读目标文档，采用局部改动，保留原有用户内容。任务不完整时标进行中、未验证或待决，不写成成功交付。已提交的变更同样属于本任务收尾范围。

## 记录纪律

现状文档原地改；已发布 CHANGELOG 保留历史，未发布区可以整理去重。known-issues 原条目更新状态和解决证据，progress 同一次任务补充已有条目。不要让每次检查重复生成记录。

多 Agent 共用文档时指定一个负责人；由负责人更新任务、历史和 ADR 编号，写前重读。子 Agent 汇报事件与证据。

## 验证

先核对当前文件、脚本定义、配置读取点和接口，不将 diff 当作最终实现。必要时运行相关本地验证；部署、迁移、重置和真实外部写入不因文档核验而获得授权。未实跑标明未运行，失败不写成通过。

遇到意外中断，下次恢复先查看已有状态并补做收尾。仅回复进度无需重新巡检。
