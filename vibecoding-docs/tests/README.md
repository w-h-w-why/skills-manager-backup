# 回归场景与验收

这些场景用于验证 Agent 的实际行为，不把静态文案检查冒充行为测试。每次实跑使用隔离临时项目，行动 Agent 仅获得任务、Skill和原始文件；评估者读取下方观察标准。无后台执行器时由独立 Agent 完成并保存真实差异、报告和验证结果。

场景数据见 [cases.json](cases.json)。对每个案例：
1. 从 before 建临时项目，按 UTF-8 原样写入字符串；working_changes 的字符串覆盖对应文件，null 表示删除对应文件。普通场景叠加 working_changes 后即可执行。
2. 若有 setup.git，先在 before 状态初始化 Git 并提交基线，保存任务开始 SHA；再应用 working_changes 并提交，确认工作树干净。将开始 SHA、任务涉及文件和 request 交给行动 Agent；它需要自行读取提交差异与当前源码，不能只凭请求描述推断结果。
3. 让独立 Agent 按 request 执行，记录输出文件与用户报告。
4. 评估者对照 expect 检查实际差异。不能只搜索Skill字符串，也不能把未执行案例标通过。
5. 重复同一任务，验证没有重复维护章节、决策编号、事件条目或无关改动。

| 场景 | 实际观察 |
| --- | --- |
| 单文档更新 | 修正目标事实；不创建AGENTS或维护目录 |
| 纯注释修改 | 收尾判断无需文档变化；所有文档字节不变 |
| 已提交接口变化 | 即使最终工作树干净仍核对本任务变更，更新接口说明 |
| 规范冲突 | 保留原业务规则并及时指出实现偏离；不宣称任务已完成 |
| 小项目初始化 | 局部维护入口只有一份、导航有效、无规则复制 |
| 沿用已有入口 | 增补既有 CLAUDE.md，保留原内容，不另建 AGENTS.md |
| ADR稀疏编号 | 以实际最大编号加一，不以文件数生成冲突编号 |
| 文档移动 | 新目标链接可达，旧路径入链同步修复 |
| 重复执行 | 无新增事实时文档保持相同，不重复事件 |

结构、YAML和路径/链接验证只验证包装正确；它们不能证明Agent遵守工作流。作者、许可证和平台自动加载行为不由这些场景推断。

可用 [结果检查器](verify_case.py) 检查实际文件不变性、指定文件的必要文本、越界安装、重复章节和 ADR 前缀。读取结果时保留原换行符，unchanged 与原始 UTF-8 快照比较：

```text
python tests/verify_case.py single-document <已经由Agent完成的隔离项目目录>
```

检查器只读文件，结构通过仍须评估业务事实、即时报告和所有链接。未提供真实执行结果时，不能把案例标记通过。
